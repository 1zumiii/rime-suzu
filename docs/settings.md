# 设置页（macOS、Windows）

设置页是一个在本机浏览器里打开的网页，用来调整桌面端的常用配置，改完可以一键重新部署。Android 的同类设置在应用的“设置”里，不需要本页。

## 启动

```bash
python3 tools/settings/suzu_settings.py
```

启动后自动打开 `http://127.0.0.1:8767/`，在终端按 Ctrl+C 退出。只需要 Python 3，不依赖第三方库。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--rime-dir` | macOS 为 `~/Library/Rime`，Windows 为 `%APPDATA%\Rime` | Rime 用户目录 |
| `--schema` | `rime_ice` | 方案名 |
| `--port` | `8767` | 端口 |
| `--no-browser` | 关 | 不自动打开浏览器 |
| `--idle-exit` | `0` | 闲置这么多分钟后自动退出（没有请求、也没在部署），`0` 为不退出 |

## 功能

- 排序参数：首位门控、名次先验系数、参与重排的候选数、四字两阶段、个人词对系数、词频系数，以及“最近用过的词”的提升位置、时间窗口、最多提升个数和词对阈值。每项都显示当前生效的值。
- 自定义表情：编辑用户目录的 `emoji_custom.txt`。格式和规则与 Android 的“自定义表情”页相同，保存后几秒内生效，不需要重新部署。
- 词库包：切换或重新安装 `packs/packs.tsv` 登记的词库包，完成后自动重新部署。用户词典保留。详见 [词库包](dictionary-packs.md)。
- 状态：用户目录、方案、当前词库包、模型与推理核心是否就位、设置文件是否已接入、上次编译方案的时间。

重新部署后，设置页读取输入法的日志，报告部署是否完成、有几项失败。词库里的重复词条提示属正常情况，只报条数。

## 配置写在哪里

设置页只写自己的文件 `suzu_settings.yaml`，不改动手写的 `<方案>.custom.yaml` 的已有内容。第一次保存时，设置页在 `<方案>.custom.yaml` 的 `patch:` 末尾加入下面一行，原文件备份为 `<方案>.custom.yaml.bak-before-settings`：

```yaml
  __patch: suzu_settings:/patch?
```

这一行让 Rime 在应用 `<方案>.custom.yaml` 的补丁之后，再应用 `suzu_settings.yaml` 里的值，所以设置页的值优先。末尾的 `?` 表示文件可选，删掉 `suzu_settings.yaml` 后部署照常，各项回到补丁里的值。网页上的“恢复”按钮作用相同，只针对单项。

`patch:` 不是文件里最后一个顶层键，或者其中已有别的 `__patch` 时，设置页不会自动修改，状态页显示“须手动接入”，按上面的写法手动加入即可。

## 安全

服务只监听 `127.0.0.1`，并校验请求的 Host 头。写操作须带启动时随机生成的令牌，令牌只嵌在本机打开的页面里，其他网页无法代为提交修改。

## 已验证的范围

macOS 鼠须管 1.1.2（librime 1.16）上已验证：自动接入、覆盖值写入后在编译产物中生效、部署结果的日志判断。Windows 小狼毫的部署程序查找与日志读取按相同逻辑实现，未在实机上验证。自测：

```bash
python3 -I tools/settings/test_suzu_settings.py
```
